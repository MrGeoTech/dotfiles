# Hyprland Lua migration notes

## Layout

```
hypr/
├── default.nix          # imports, packages, mako, keyring  (edited)
├── config.nix           # the HM module: extraLuaFiles wiring (rewritten)
├── colors.nix           # shared Catppuccin Mocha palette    (new)
├── hyprpaper.nix        # hyprlang, unchanged behaviour      (de-hardcoded)
├── hypridle.nix         # hyprlang, untouched
├── hyprlock.nix         # hyprlang, now reads colors.nix
├── lua/
│   ├── lib/keys.lua     # bind helpers            -> hypr/lib/keys.lua
│   ├── look-and-feel.lua                          -> hypr/10-look-and-feel.lua
│   ├── rules.lua                                  -> hypr/20-rules.lua
│   ├── binds.lua                                  -> hypr/30-binds.lua
│   └── autostart.lua                              -> hypr/40-autostart.lua
└── hypr/                # unchanged: scripts/, wallpapers
```

`00-vars.lua` is generated by `config.nix` from `hostName` — it is the only
place Nix still writes Lua, and it holds nothing but data.

Home-manager writes `hyprland.lua` itself: it sets `package.path` to the hypr
config dir and emits one `require()` per `autoLoad = true` file, in
attribute-name order. Hence the numeric prefixes — they control load order.

## What changed functionally

Everything else is a straight translation. Four deliberate changes:

1. **`SUPER + CTRL + R` opens a resize submap.** `hjkl` resizes by 20px and
   repeats when held, `SHIFT + hjkl` by 100px, `Escape` / `Return` / `q`
   exits. The old `SUPER + CTRL + SHIFT + hjkl` binds still work.
2. **Media and brightness keys got `locked = true, repeating = true`.** They
   now work with hyprlock up and repeat when held, matching upstream's example
   config. Drop the opts table in `binds.lua` if you'd rather they didn't.
3. **`hyprpaper` and `gnome-keyring-daemon` are commented out of autostart.**
   `services.hyprpaper.enable` and `services.gnome-keyring.enable` already
   start both as systemd user services; you were launching two of each.
4. **`$BROWSER` became `os.getenv("BROWSER") or "firefox"`.** Lua has no
   `$var` interpolation, and relying on the shell to expand it inside
   `exec_cmd` is fragile. Change the fallback to whatever you actually use.

## Verify before you commit

A few `hl.dsp.*` names came from the old generated config rather than from
upstream docs — `window.kill()`, `window.fullscreen({ mode = ... })`,
`layout("togglesplit")`, `exit()`, and the `"r+1"` / `"r-1"` workspace
selectors. They're plausible but worth a check, and 0.56 makes that easy:

```bash
hyprland --verify-config          # parse + type errors, no session needed
hyprctl                           # 0.56 ships a Lua REPL; poke at hl.dsp here
```

Runtime type errors (wrong argument type to an `hl.*` call) don't abort the
config — they pop a notification and carry on — so a clean `--verify-config`
is not proof that every dispatcher name resolved.

## LSP

Hyprland ships LuaLS type definitions under `meta/` in its repo. Generate them
once, drop them somewhere stable, and point a `.luarc.json` at that directory
plus `~/.config/hypr`. With `lua-language-server` installed you get completion
on `hl.dsp.*`, which is the single biggest practical win over the Nix route.

## Iterating without a rebuild

Files written by `extraLuaFiles` land read-only in the Nix store, so
Hyprland's save-and-reload loop doesn't work on them. While you're actively
tuning, symlink the working tree instead:

```nix
home.file.".config/hypr/30-binds.lua".source =
  config.lib.file.mkOutOfStoreSymlink "/home/mrgeotech/nix/hypr/lua/binds.lua";
```

Comment the matching `extraLuaFiles` entry out while that's active — two
things managing one path is a home-manager collision error. Move it back once
the config settles.

## Rollback

`config_old.nix` and `default_old.nix` still describe a working hyprlang
setup. If 0.56 misbehaves, `configType = "hyprlang"` plus those files gets you
back, at least until the hyprlang backend is removed from home-manager.
